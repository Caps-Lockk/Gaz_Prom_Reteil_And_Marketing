## Предлагаемая механика

Персональный возврат **0,50 рубля за литр на первые 70 литров** в расчётном месяце. Применяем к клиенту, если выполнены все условия: сегмент «Ценочувствительный»; покупка хотя бы в одном из последних трёх месяцев; мобильное приложение; согласие на marketing push; последняя наблюдаемая цена своей АЗС выше средней цены конкурентов **строго более чем на 0,50 руб./л**. Повторная проверка согласия нужна непосредственно перед отправкой.

Текущие данные месячные, а не потоковые. Для запуска оффера в приложении в реальном времени потребуется отдельная интеграция с актуальным мониторингом цен.

## Формулы

В таблицах дано `Средняя маржа`, руб./т, и `Средний OPEX`, руб./т. При предположении, что маржа **не включает OPEX**, вклад на литр:

\[
m_i = (\mathrm{Margin}_{r,f} - \mathrm{OPEX}_{r,f})\cdot \frac{\rho_f}{1000}, \qquad [\mathrm{руб/л}]
\]

где `ρ` дана в т/м³. Если расходы уже включены в определение маржи, повторное вычитание OPEX завышает оценку затрат; это необходимо согласовать с владельцем экономики.

Для клиента `i`, у которого базовые литры `L_i`:

\[
\begin{aligned}
L_i' &= L_i(1+u),\\
\mathrm{Cost}_i &= r\cdot\min(L_i', L_{cap}),\\
\mathrm{IncrementalContribution}_i &= (L_i'-L_i)m_i,\\
\mathrm{IncrementalProfit}_i &= (L_i'-L_i)m_i - \mathrm{Cost}_i.
\end{aligned}
\]

**Ключевой момент:** начисляем бонусы на *весь субсидируемый объём*, включая литры, которые клиент купил бы и без скидки. Нельзя считать только стоимость бонусов на дополнительные литры.

## Результат модели, май 2024 как базовый месяц

| Параметр | Значение |
|---|---:|
| Число кандидатов | 3 568 |
| Текущий объём кандидатов | 339 970,60 л |
| Предполагаемый uplift | +5% |
| Дополнительный объём | 16 998,53 л |
| Вклад от дополнительных литров | 169 599,69 ₽ |
| Полная стоимость начисленных бонусов | 88 164,90 ₽ |
| **Чистый инкрементальный вклад** | **+81 434,79 ₽** |
| **Breakeven uplift** | **2,584%** |

Числа соответствуют принятому исследовательскому определению сегментов и маржи. Прирост 5% **не измерен**. Это лишь один сценарий, а не фактически полученная прибыль. Нет дополнительных затрат на коммуникацию, интеграцию, инкрементальные СТиУ, устойчивый LTV и динамическую реакцию конкурентов.

## Реальные критерии запуска

1. Определить ожидаемый *incremental uplift* по A/B-тесту, а не присваивать 5% каждому клиенту без основания.
2. Получить корректную вкладовую маржу от финансового подразделения, проверить происхождение OPEX.
3. Ввести лимиты бюджета и частоты предложений, минимальный вклад, окно действия и контроль «каннибализации».
4. Использовать policy engine: отправлять бонус только при прогнозируемом положительном **инкрементальном** вкладе, подтверждаемом экспериментом.

Код: [`economics.py`](../src/fuel_elasticity/economics.py). Параметры доступны через CLI: `--rebate`, `--cap`, `--uplift`, `--price-gap`.
